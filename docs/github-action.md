# Check a package with GitHub Actions

Run Pledge after checkout and your package's normal build. Its container includes
Pledge, Node.js, npm, and a default TypeScript compiler. No Pledge installation,
GitHub App, or token is needed to compare a public npm package.

Use a Linux x86-64 runner, such as `ubuntu-24.04`. The example follows the latest
published release automatically, including breaking updates. Replace `latest`
with a published `vX.Y.Z` tag from [Releases](https://github.com/stentorian-io/pledge/releases)
to control upgrades.

```yaml
name: Package compatibility
on: pull_request
permissions:
  contents: read
jobs:
  compatibility:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npm run build
      - uses: stentorian-io/pledge@latest
```

Omit install/build steps only when the checkout already has its publishable
files. Use your normal package manager and Node setup for those steps; the
container's tools are available inside the Pledge step. Pledge disables npm
lifecycle scripts and does not build missing outputs.

With no inputs, Pledge discovers publishable root and workspace packages and
compares each with the highest published version without a prerelease suffix
in the same major. Breaking findings for local `0.x` packages are advisory;
breaking findings for packages at `1.x` or later fail the step. Acquisition/tool
errors and incomplete analysis fail regardless of the package's version.
Findings and diagnostics appear in the step log and job summary. A clean result
is subject to the documented [analysis coverage](language-coverage.md).

## Select the package and baseline

The [package selection reference](package-selection.md) defines discovery,
baseline selection, and aggregation across multiple packages.

```yaml
- uses: stentorian-io/pledge@latest
  with:
    path: packages/core
    against: '1.4.2'
```

| Input | Default | Meaning |
| --- | --- | --- |
| `path` | Automatic discovery | Check exactly this package directory inside the checkout; `.` selects only the root |
| `against` | Highest published non-prerelease in each package's major | Exact published version or npm dist-tag, resolved separately for every selected package |

The package name comes from its manifest; npm configuration chooses the
registry. A dist-tag resolves at the start of the check, and the summary names
the resolved versions. Version ranges, URLs, local baseline paths, and comparing
two arbitrary package names are not supported. npm/Yarn-style `workspaces` and
pnpm's explicit `packages` patterns select members; private packages are skipped.
Without workspace declarations, automatic discovery checks the root package.
An unavailable baseline fails the action, including an unpublished package;
use the CLI without `--against` for first-publish analysis. To retain the earlier
single-package selection, set `path: .` and `against: latest` explicitly.

`latest` is a moving Git tag. It advances only after the release assets and
container pass public-access, checksum, and provenance checks. Retrying an older
release does not move it backward. Every tagged action still pins its matching
versioned container; `latest` does not depend on a mutable Docker image tag.

Use an exact Pledge release tag or its commit SHA for reproducible version
selection. There is no moving `v0` alias: minor releases before 1.0 can contain
breaking changes. `@main` is valid GitHub syntax, but can reference the next
version's image while publication is still running. Use `@latest` to follow
completed publications.

## Private registries and TypeScript

Use a project `.npmrc` referencing an environment token, as described in
[registry configuration](ci.md#registries-and-credentials), then pass that token
to the Pledge step:

```yaml
- uses: stentorian-io/pledge@latest
  env:
    NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

Configuration files and CA certificates must be accessible inside the container.
Runner-only paths generated by another setup action are not automatically
mounted; a checked-out `.npmrc` with environment substitutions works directly.
The action combines the checkout root's `.npmrc` with accessible user npm
configuration in a temporary file, preserving user credentials and root settings
for pnpm/Yarn members as well as npm workspaces. Original files are unchanged.
Keep credentials in secrets, not in the file. Secret availability on fork PRs
follows GitHub's usual rules.

The project's JavaScript TypeScript compiler takes precedence when installed.
Otherwise the image supplies TypeScript 5.9.3, with Node.js 24.22.2 and npm
11.19.0. Runtime/peer dependencies still need registry access. A pinned baseline
does not freeze transitive dependencies; see [dependency preparation](ci.md#typescript-and-dependency-preparation).
The action currently supports Linux x86-64 only, including self-hosted Linux
runners with Docker. Windows, macOS, and ARM runners are not supported.

## Read the result

Give the step an `id` to consume its outputs in a later step with `if: always()`:

| Output | Values |
| --- | --- |
| `status` | `clean`, `advisory`, `breaking`, `error`, or `incomplete` |
| `exit-code` | `0` for clean/advisory, `1` for breaking, `2` for errors, `3` for incomplete analysis |

Findings preserve the [CLI severity contract](results.md). The action permits
breaking findings while a package's local major remains `0`; the standalone
CLI continues to return `1` for those findings. Errors take precedence over
incomplete analysis, then blocking breaking findings, advisory findings, and
clean results. Every selected package's findings remain visible.
Outputs are available when
the entrypoint completes, including a failed comparison; image-pull failures
and cancelled jobs may have no outputs. The action adds no report files to the
package. Its summary truncates exceptionally large results and points to the
complete step log. For a retained JSON report, use the CLI's
[report output](ci.md#exit-codes-and-output).
